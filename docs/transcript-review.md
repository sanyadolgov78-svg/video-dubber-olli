# Проверка транскрипта

Конвейер **дважды останавливается и ждёт человека**. Пока вы не подтвердите
правки, озвучка не начнётся. Это осознанное решение: распознавание речи
всегда ошибается, а ошибка в тексте идёт дальше в озвучку и в субтитры.

## Две остановки

### 1. После распознавания

Конвейер сделал транскрибацию и перевод, создал таблицу для проверки и
остановился.

```
work/<имя>/<имя>.table.rtf          ← таблица для проверки (Word)
work/<имя>/<имя>.table.json         ← служебные данные
work/<имя>/<имя>.table.rtf.orig     ← эталон, с которым сравнивается ваша правка
work/<имя>/<имя>.meta.json          ← язык оригинала и пол говорящего
```

Столбцы таблицы: **таймкоды | оригинал | перевод на fr**.

Правьте текст в Word и сохраняйте. Конвейер сам заметит изменение и пойдёт
дальше: полишинг → озвучка → экспорт.

### 2. После полишинга

Полишинг может испортить смысл. Конвейер снова ждёт вашей проверки, прежде
чем озвучивать.

## Два способа вносить правки

### Способ 1: Word (рекомендуется)

Откройте `.table.rtf`, исправьте текст в нужных ячейках, сохраните.
Видны таймкоды и три столбца сразу.

### Способ 2: Блокнот

Создайте или откройте файл `<имя>.transcript_otpravka.txt`. Формат строк:

```
[12.50] RU: Привет, как дела?
[12.50] FR: Bonjour, comment ça va ?
[15.20] FR: Je vais bien, merci.
```

- Префикс `[секунды]` перед текстом не важен для применения правок, но
  помогает вам сориентироваться — строки применяются по порядку.
- `RU:` — правка оригинала. Если правите только оригинал, французский
  пересчитывается автоматически (при `retranslate_on_source_edit: true`).
- `FR:` — правка перевода.
- Строки без префикса `RU:`/`FR:` или с неизвестным префиксом игнорируются.

Конвейер сам переносит правки в таблицу и продолжает работу.

## Как конвейер понимает, что правка сделана

Механизм — `rtf_table.table_is_edited()` (`pipeline/rtf_table.py:455`):

1. При генерации таблицы рядом кладётся копия `.orig`
2. При следующем запуске файлы сравниваются побайтно
3. Если содержимое отличается — правка считается сделанной
4. Для `.txt` — сравнивается содержимое строк с текущей таблицей

**Важно:** сравнение идёт по содержимому, а не по времени изменения файла.
Открыть файл в Word и сохранить без правок — не считается правкой.

Если правок несколько, конвейер принимает их по одной: каждая версия
таблицы проходит цикл заново.

## Настройка

`config.json`:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `retranslate_on_source_edit` | `true` | Правка оригинала пересчитывает перевод |
| `polish_required` | `true` | `true` — без Ollama не идти дальше |
| `dub_enabled` | `true` | `false` — только распознавание и перевод, без озвучки |

## Облачный режим

При работе через сервер шаг проверки переезжает на диск:

```
VideoDubbing/
├── 1_inbox/     ← сюда кладёте ролики
├── 2_review/    ← сюда сервер кладёт .table.rtf и .transcript_otpravka.txt
├── 3_rights/    ← ваши исправленные файлы кладёте обратно сюда
└── 4_done/      ← готовые озвученные ролики
```

Порядок: ролик в `1_inbox` → распознавание → файлы на проверку в
`2_review` → вы правите и кладёте в `3_rights` → конвейер продолжает →
готовый ролик в `4_done`.

## Не зависает ли конвейер

Нет. Проверка — это ожидание нового файла, а не блокировка. В режиме
`--watch` конвейер опрашивает папки каждые `interval` секунд и продолжает,
как только замечает правку. Пока вы не вносите правки, ролик просто ждёт.
